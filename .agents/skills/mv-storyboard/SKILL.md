# MV分镜脚本生成 Skill

## 概述

本Skill用于从ASS格式歌词文件自动生成MV分镜脚本。通过解析歌词时间戳、分析歌曲风格与情感、智能匹配人物库形象，最终输出包含18个维度分镜信息和Seedance优化prompt的结构化脚本。

## 触发条件

当用户需要以下操作时触发本Skill：
- 生成MV分镜脚本 / 创建MV storyboard
- 从歌词生成视频脚本
- 解析ASS歌词文件并编排剧情
- 创作AI MV / Seedance MV制作
- 为歌曲生成分镜

## 输入参数

| 参数 | 必需 | 说明 | 默认值 |
|------|------|------|--------|
| ass_file | 是 | ASS歌词文件路径 | - |
| character_library | 否 | 人物库目录路径 | `人物库/` |
| output_dir | 否 | 输出目录 | ASS文件同目录 |
| custom_character | 否 | 自定义人物描述（当人物库无匹配时使用） | - |
| narrative_override | 否 | 手动指定叙事风格（覆盖自动匹配） | - |

## 执行流程

严格按照以下7个步骤顺序执行，每步完成后输出该步的中间结果供用户确认。

### Step 1 - 读取与解析ASS文件

#### 1.1 编码处理

ASS文件可能使用不同编码，按以下策略处理：

1. 先以 UTF-8 编码读取文件内容
2. 检测是否出现乱码特征：
   - 出现连续的 `\uFFFD`（替换字符）
   - 出现大量非预期字符（如 `\u0000` 到 `\u001f` 之间的控制字符）
   - 中文Style名（如"男："、"女："）变为乱码
3. 若检测到乱码，以 GBK 编码重新读取
4. 解析成功后统一以 UTF-8 文本处理

**Bash编码检测示例**（Windows PowerShell环境）：
```powershell
# 尝试UTF-8读取，检测乱码后回退GBK
$content = Get-Content $assFile -Encoding UTF8 -Raw
if ($content -match '\uFFFD' -or $content -notmatch '[\x{4e00}-\x{9fff}]') {
    $content = Get-Content $assFile -Encoding Default -Raw
}
```

#### 1.2 ASS结构解析

ASS文件包含三个段落：`[Script Info]`、`[V4+ Styles]`、`[Events]`。

**只需关注 `[Events]` 段**，提取所有 `Dialogue:` 行。

每行Dialogue格式：
```
Dialogue: Layer,Start,End,Style,Name,MarginL,MarginR,MarginV,Effect,Text
```

使用正则提取各字段：
```
正则：^Dialogue:\s*(\d+),([^,]+),([^,]+),([^,]+),([^,]*),([^,]*),([^,]*),([^,]*),([^,]*),(.*)$
- Group 1: Layer（图层，通常为0）
- Group 2: Start（开始时间，格式 H:MM:SS.cs）
- Group 3: End（结束时间，格式 H:MM:SS.cs）
- Group 4: Style（样式名，标识歌手角色）
- Group 10: Text（歌词文本，含karaoke标签）
```

#### 1.3 Karaoke标签剥离

Text字段包含karaoke标签 `{\K28}` 或 `{\k28}`，需剥离得到纯歌词：

```
正则：/\{\\[Kk]\d+\}/g
替换为：空字符串
```

同时剥离其他ASS覆盖标签：`/\{[^}]*\}/g`

#### 1.4 歌手角色识别

通过Style字段识别歌手角色：
- 含"男"→ 男声
- 含"女"→ 女声
- 含"合"→ 合唱
- 含"配唱"或"一词"→ 对唱/配唱
- "Default" → 默认（需根据上下文判断）

#### 1.5 时间解析

将 `H:MM:SS.cs` 格式转换为秒数：
```
function parseTime(timeStr):
    parts = timeStr.split(':')
    hours = parseInt(parts[0])
    minutes = parseInt(parts[1])
    seconds = parseFloat(parts[2])
    return hours * 3600 + minutes * 60 + seconds
```

#### 1.6 输出

解析完成后，得到一个歌词行数组：
```
[
  { start: 14.97, end: 17.33, singer: "男", text: "因为太漂亮", raw: "原始Text" },
  { start: 17.33, end: 19.36, singer: "男", text: "男人们不安分", raw: "..." },
  ...
]
```

总时长 = 最后一行的 end 时间。

### Step 2 - 歌曲结构分析

#### 2.1 段落识别

通过三个信号综合判断歌曲段落结构：

**信号1 - 时间间隔**：
- 第一句歌词开始前的时间 = 前奏（Intro）
- 相邻歌词行之间间隔 > 3秒 = 间奏（Interlude）
- 最后一句歌词结束后的时间 = 尾奏（Outro）

**信号2 - 歌词重复**：
- 检测歌词文本是否重复出现
- 重复段落通常为副歌（Chorus）
- 首次出现的重复段落标记为主歌（Verse），重复出现标记为副歌

**信号3 - 歌手变化**：
- 男声→女声→合唱 的变化模式通常出现在副歌
- 单人独唱段落通常为主歌

#### 2.2 段落标注规则

| 段落类型 | 标注 | 识别条件 |
|---------|------|---------|
| 前奏 | `intro` | 第一句歌词前的部分 |
| 主歌A | `verseA` | 歌曲开始的第一段独唱 |
| 主歌B | `verseB` | 第二段独唱（如有） |
| 预副歌 | `preChorus` | 主歌与副歌之间的过渡段 |
| 副歌 | `chorus` | 重复出现的段落，或合唱段落 |
| 桥段 | `bridge` | 结构上不同于前后段的段落 |
| 间奏 | `interlude` | 歌词间 >3秒的间隔 |
| 尾奏 | `outro` | 最后一句歌词后的部分 |

#### 2.3 歌曲风格判断

基于以下维度综合判断歌曲风格：

**维度1 - 歌词关键词**：
- 爱情词（爱、心、恋、想、念）→ 抒情情歌
- 校园词（青春、少年、夏天、课桌）→ 校园青春
- 古风词（江湖、剑、月、花、琴）→ 古风/中国风
- 都市词（城市、霓虹、地铁、咖啡）→ 都市流行
- 分手词（再见、离开、眼泪、心痛）→ 伤感情歌

**维度2 - 节奏密度**：
- 计算每秒歌词字数 = 总字数 / 总时长
- 高密度（>1.5字/秒）→ 快节奏
- 中密度（0.8-1.5字/秒）→ 中速
- 低密度（<0.8字/秒）→ 慢板

**维度3 - 语言**：
- 中文 → 中文歌曲
- 韩文 → 韩文歌曲
- 英文 → 英文歌曲
- 混合 → 多语言歌曲

**维度4 - Style多样性**：
- 只有"Default" → 独唱
- 有"男"+"女" → 对唱/合作
- 有"合" → 合唱段落

#### 2.4 情感基调分析

通过歌词内容判断情感走向：
- 情感词频次统计（喜悦词 vs 伤感词）
- 歌词叙事走向（起→承→转→合）
- 输出情感关键词：如"甜蜜"、"伤感"、"怀念"、"坚定"等

#### 2.5 输出

```
{
  songStyle: "抒情情歌",          // 歌曲风格
  emotionalTone: "伤感怀念",      // 情感基调
  language: "韩文",              // 歌曲语言
  duration: 196.39,              // 总时长（秒）
  tempo: "中速",                 // 节奏
  sections: [                    // 段落结构
    { type: "intro", start: 0, end: 14.97 },
    { type: "verseA", start: 14.97, end: 28.82, lyrics: [...] },
    { type: "preChorus", start: 29.40, end: 34.11, lyrics: [...] },
    { type: "chorus", start: 44.62, end: 58.06, lyrics: [...] },
    ...
  ],
  emotionalArc: "起(平静)→承(升温)→转(高潮)→合(回落)"
}
```

### Step 3 - 叙事风格匹配

根据Step 2的歌曲风格，参照叙事风格匹配表选择叙事风格：

| 歌曲风格 | 叙事风格 | 分镜特点 |
|---------|---------|---------|
| 抒情情歌/都市情歌 | 线性剧情叙事 | 有头有尾的爱情故事，场景连贯 |
| 快节奏流行/电子 | 蒙太奇快切 | 快速切换，节奏感强，视觉冲击 |
| 古风/中国风 | 意境叙事 | 诗意画面，慢节奏，注重氛围 |
| 校园青春 | 青春成长叙事 | 校园场景，青涩互动，明亮色调 |
| 街头/嘻哈/R&B | 都市街头风格 | 城市实景，个性表达，动态运镜 |
| 慢板抒情/民谣 | 情感氛围叙事 | 意象化画面，情绪流动，大量空镜 |
| 默认/无法判断 | 通用情感叙事 | 混合叙事，平衡剧情与氛围 |

详细匹配规则和分镜编排策略见 `assets/narrative-style-guide.md`。

匹配完成后输出：
```
{
  narrativeStyle: "线性剧情叙事",
  storyline: "一对恋人在城市中从相遇、相恋到因误解而分离，最终在雨夜重逢的故事",
  visualTone: "冷暖交替，前期暖调甜蜜，中期冷调疏离，末期暖调回归"
}
```

### Step 4 - 人物匹配

#### 4.1 读取人物库

读取 `人物库/` 目录下所有 `.md` 文件。每个文件结构：
```markdown
# XXX.png 人物形象描述
## 女主形象
- **年龄估计**：约XX岁
- **人物形象风格**：XXX
- ...
## 男主形象
- **年龄估计**：约XX岁
- **人物形象风格**：XXX
- ...
## 整体风格
**适配歌曲风格**：XXX，适合表达XXX的情感主题。
```

#### 4.2 匹配逻辑

1. 提取每个MD文件的"适配歌曲风格"字段
2. 将Step 2分析得到的歌曲风格与各人物的适配风格进行语义匹配
3. 匹配优先级：
   - 精确匹配（如"古风歌曲" == "古风歌曲"）
   - 语义近似匹配（如"抒情情歌" ≈ "都市情歌"）
   - 年龄适配性（歌曲主题与人物年龄是否匹配）
4. 选择匹配度最高的人物组合

#### 4.3 自定义人物

当人物库无合适匹配时，按以下格式自定义新人物：
```markdown
- **年龄估计**：约XX岁
- **人物形象风格**：XXX
- **发型**：XXX
- **上装**：XXX
- **下装**：XXX
- **鞋子**：XXX
- **饰品**：XXX
```

### Step 5 - 分镜编排

#### 5.1 分镜划分原则

1. **按歌曲段落划分**：每个段落（前奏/主歌/副歌/桥段/间奏/尾奏）对应一组分镜
2. **按歌词行细化**：段落内每1-3句歌词对应一个分镜
3. **空镜分配**：
   - 前奏 → 开场空镜（环境交代）
   - 间奏 → 过渡空镜（情绪缓冲）
   - 尾奏 → 结尾空镜（余韵收束）
   - 歌词间隔 > 2秒 → 可插入短空镜
4. **分镜时长约束**：
   - 每个shot的时长必须为**整数秒**（向下取整，如5.97s→5s）
   - 最短 **4秒**，最长 **15秒**
   - 若歌词行时长<4秒，需合并相邻歌词行为一个shot
   - 若歌词行时长>15秒，需拆分为多个shot
   - 空镜时长同样遵守4-15秒约束

#### 5.2 分镜字段填充

为每个分镜分配18个维度：

| 字段 | 填充逻辑 |
|------|---------|
| Shot编号 | 顺序编号 + 场景名（如"Shot 01 - 街角初遇"） |
| 时间戳 | 取自ASS解析的Start/End时间 |
| 歌词 | 取自ASS解析的纯歌词文本 |
| 歌手 | 取自ASS解析的歌手角色 |
| 歌曲段落 | 取自Step 2的段落标注 |
| 镜头类型 | 空镜/人物镜/双人镜，根据是否有歌词和人物决定 |
| 人物 | 取自Step 4匹配的人物编号或自定义描述 |
| 景别 | 参照 `assets/camera-language-reference.md` 选择 |
| 角度 | 参照 `assets/camera-language-reference.md` 选择 |
| 运镜 | 参照 `assets/camera-language-reference.md` 选择 |
| 场景描述 | 根据歌词内容和叙事风格设计 |
| 人物动作 | 根据歌词情感和叙事推进设计 |
| 色调 | 根据情感基调和叙事风格选择 |
| 光影 | 根据场景和情绪氛围选择 |
| 情绪氛围 | 根据歌词内容和情感走向判断 |
| 节奏 | 根据歌曲节奏密度和段落类型选择 |
| 转场 | 根据相邻分镜的关系选择 |
| Seedance Prompt | 参照Step 6生成 |

#### 5.3 编排连贯性原则

- 同一叙事场景内的分镜保持人物着装一致
- 场景转换时使用转场（叠化/闪白/匹配剪辑等）过渡
- 副歌段落使用更具视觉冲击力的镜头（特写/动态运镜）
- 主歌段落使用较平稳的镜头（中景/固定/缓慢运镜）
- 情感高潮处使用慢镜头或特写
- 色调随情感走向变化（暖→冷→暖 或 冷→暖）

#### 5.4 Shot数量控制

**硬性上限：最多不超过23个shot（包括空镜）**

当初步编排的shot数量超过23个时，通过以下方式缩减：

1. **合并相邻shot**：将同一场景、同一叙事段落内相邻的shot合并为一个
   - 合并后时长仍需满足4-15秒约束
   - 合并时保留关键动作和情绪转折，删减冗余动作
2. **删减次要shot**：
   - 优先保留副歌段落的分镜（视觉高潮）
   - 优先保留情感转折点的分镜
   - 可删减重复性较高的主歌分镜
3. **空镜精简**：
   - 前奏空镜保留1个（开场交代）
   - 间奏空镜保留1-2个（情绪缓冲）
   - 尾奏空镜保留1个（余韵收束）
   - 歌词间隔短空镜可合并到相邻shot中
4. **验证清单**：
   - 最终shot数量 ≤ 23
   - 每个shot时长为整数秒
   - 每个shot时长在4-15秒范围内
   - 所有shot的时间戳连续覆盖歌曲总时长（无缝隙、无重叠）

### Step 6 - Seedance Prompt生成

本步骤融合了 Seedance 2.0 官方提示词优化规范，采用工程化写法生成高质量prompt。

#### 6.1 八大核心要素公式

每个分镜生成一个Seedance优化prompt，采用八大要素结构化写法：

```
[精准主体] + [动作细节] + [场景环境] + [光影色调] + [镜头运镜] + [视觉风格] + [画质] + [约束条件]
```

> 好的提示词不是文案型形容，而是工程型指令：谁、在什么场景、做什么动作、镜头如何运动。前2项必填，后6项按需补全。

#### 6.2 各部分写作规则

**[精准主体]**（必填）：
- 从人物库MD提取关键视觉特征：年龄、发型、服装、配饰
- 简洁但具体，避免模糊描述
- 同一场景的多个分镜保持人物描述一致
- 例："一位22岁年轻男性，深色短发，穿藏青色宽松圆领卫衣和黑色阔腿工装裤"

**[动作细节]**（必填，Seedance 2.0 核心要求）：
- **肢体细化 + 程度量化**：手/腿/头/肩背 + 幅度/速度/力度
- **优先低缓连续小动作**，规避狂奔/大跳/剧烈翻滚等高爆发动态
- **补充动作过渡衔接**：前后惯性承接（如"借着转身惯性顺势抬手"）
- **情绪具象外化**：用具体身体细节代替"悲伤/愤怒"等抽象词
  - 悲伤 → "肩膀微微颤抖、眼眶泛红、手指攥紧衣角"
  - 紧张 → "手指无意识攥紧、呼吸微顿、目光闪躲"
  - 释然 → "肩膀缓缓松下、嘴角微扬、闭眼深呼吸"
- 与歌词情感呼应
- 例："男主靠在街边墙上，双手插在卫衣口袋里，目光痴迷望向远处，嘴角带着苦涩微笑"

**[场景环境]**（核心部分，必须充分描写场景氛围感）：
- 具体环境：地点、时间、天气、氛围
- **场景氛围感强化**（必须包含以下至少3项）：
  - 空气质感：雾气/雨雾/烟尘/干燥/潮湿
  - 光线状态：直射/散射/逆光/侧光/漫射光
  - 环境动态：风吹树叶/雨滴落地/蒸汽升腾/灰尘飞舞
  - 色温感知：暖光/冷光/混合光/色温过渡
  - 声画暗示：通过视觉元素暗示声音氛围（如空旷街道暗示寂静）
  - 空间纵深：前景/中景/远景的环境层次
- 感官细节：声音、气味、温度（通过视觉暗示）
- 例："城市街道夜色，雨后湿润的人行道上残留着水渍，空气中弥漫着残留水汽与微凉夜风，远处霓虹灯牌在薄雾中模糊闪烁"

**[光影色调]**（强化氛围感的关键维度）：
- 明确色调方向和光源
- **氛围光影强化**（必须包含以下至少2项）：
  - 光源描述：自然光/人工光/混合光，光源方向
  - 光影质感：硬光/软光/漫射光，阴影浓淡
  - 色温层次：主色调+辅助色+点缀色
  - 环境光互动：光线与雾气/雨滴/灰尘的互动效果
  - 情绪光影：用光影传达情绪（如暗角表压抑、高光表希望）
- 例："冷蓝色调为主，路灯暖黄侧光勾勒面部轮廓，雨后湿润墙面反射微弱光斑，空气中水汽微粒在光柱中飘浮"

**[镜头运镜]**：
- 使用专业术语：景别 + 角度 + 运镜方式
- **一镜一运镜原则**：单镜头只指定1种运镜方式（推/拉/摇/移/固定/跟拍择一），**禁止叠加**（如"推+摇"同时出现）
- 例："中景，平视角度，缓慢推进运镜"

**[视觉风格]**：
- 开头明确整体风格，如"电影级MV风格"、"纪录片风格"、"诗意叙事风格"
- 包含氛围关键词，如"都市抒情"、"青春校园"、"古风意境"
- 动漫/非写实场景必须显式锚定风格（如"2D日漫风格"/"赛博朋克冷蓝紫色调"）防止风格漂移到写实

**[画质]**（默认必挂）：
- 默认画质包：`高清，细节丰富，电影质感，色彩自然，光影柔和`
- 简单场景可压缩为短句"高清电影质感"

**[约束条件]**（强制兜底约束包，每个prompt末尾必须挂载）：
- **稳定包**（必挂）：`人物面部稳定不变形、五官清晰、动作连贯自然，不僵硬，无穿模无卡顿`
- **字幕兜底**（必挂）：`保持无字幕，避免生成任何文字或字幕`
- **水印/Logo兜底**（必挂）：`不要生成水印，不要生成Logo`
- **双胞胎兜底**（双人镜必挂）：`视频全程禁止出现外形、着装、配饰完全一致的人物，禁止生成同款分身、双胞胎效果`
- 物理约束（如需要）："人物比例符合现实世界物理规律"

#### 6.3 Prompt写作注意事项

1. 统一使用中文（Seedance对中文prompt理解最佳）
2. 每个prompt控制在80-200字，信息密度高但不冗余
3. 避免使用"可能"、"也许"等不确定词汇
4. 避免描述Seedance无法生成的元素（如文字、字幕、复杂UI界面）
5. 空镜prompt不包含人物描述部分，**但场景氛围感描写需更加充分**（空镜靠氛围叙事）
6. 同一场景的多个分镜保持人物描述一致
7. **场景氛围感是prompt的核心竞争力**：每个prompt必须让读者能"感受到"那个场景的空气、光线、温度和情绪，而非仅仅"看到"画面
8. **一镜一运镜**：单镜头只指定1种运镜方式，禁止推拉摇移叠加
9. **动作优先低缓**：优先低缓连续小动作，规避狂奔/大跳/剧烈翻滚等高爆发动态
10. **情绪具象外化**：用具体身体细节代替"悲伤/愤怒"等抽象词
11. **强制兜底**：每个prompt末尾必须挂载画质包+稳定包+水印Logo兜底；双人镜追加双胞胎兜底

详细写作指南见 `assets/seedance-prompt-guide.md`。

#### 6.4 特殊字符规范

在prompt中需要表示声音信息时，使用以下统一符号：

| 信息类型 | 符号 | 示例 |
|------|------|------|
| 背景音乐 | `（）` | `（背景中播放着快节奏的摇滚乐）` |
| 音效 | `<>` | `<远处传来狗叫声>` |
| 台词 | `{}` | `{你好，世界}` |
| 字幕/标题 | `【】` | `【第一章：启程】` |

> MV分镜中一般不使用台词和字幕符号（歌词作为画面外音轨存在），但可在蒙太奇空镜中使用音效符号增强氛围。

#### 6.5 八大要素自检清单

每个prompt生成后，逐项核对以下8项：

| # | 要素 | 必要性 | 缺失时处理 |
|---|------|--------|-----------|
| 1 | 精准主体（谁） | **必填** | 从人物库提取绑定 |
| 2 | 动作细节（在干什么） | **必填** | 默认低缓连续小动作 |
| 3 | 场景环境（在哪） | 按需 | 含氛围感描写（至少3项） |
| 4 | 光影色调（什么氛围） | 按需 | 含氛围光影（至少2项） |
| 5 | 镜头运镜（怎么拍） | 按需 | 一镜一运镜，禁止叠加 |
| 6 | 视觉风格（什么画风） | 按需 | 开头风格定义 |
| 7 | 画质（清晰度） | 按需 | 默认画质包 |
| 8 | 约束条件（兜底） | 按需 | 稳定包+字幕兜底+水印Logo兜底 |

## 注意事项

1. **编码优先**：始终先尝试UTF-8，GBK仅作为回退方案
2. **歌词完整性**：剥离karaoke标签时不要损坏歌词文本本身
3. **时间精度**：保留ASS原始的厘秒精度（0.01秒）
4. **人物一致性**：同一叙事场景内人物着装必须一致
5. **空镜必要性**：不要为了凑数生成空镜，空镜必须服务于叙事或情绪
6. **叙事连贯**：分镜之间必须有逻辑关联，不能是孤立的画面堆砌
7. **歌词对应**：每个分镜的歌词必须与时间戳精确对应，不可错位
8. **一镜一运镜**：单镜头只指定1种运镜方式，禁止推拉摇移叠加
9. **动作优先低缓**：优先低缓连续小动作，规避狂奔/大跳/剧烈翻滚等高爆发动态
10. **情绪具象外化**：用具体身体细节代替"悲伤/愤怒"等抽象词
11. **强制兜底**：每个prompt末尾必须挂载画质包+稳定包+字幕兜底+水印Logo兜底；双人镜追加双胞胎兜底
12. **Seedance限制**：prompt中不要包含Seedance无法生成的内容（文字、字幕、复杂UI界面）
